# 0003. Правила — функции домена

**Контекст.** Было два пути: собрать правила в методах корня агрегата
или держать сущности простыми, а правила — снаружи. Места (`Seat`) уже
были устроены вторым способом: только состояние и свои инварианты.

**Решение.** Сущности хранят состояние и охраняют свои инварианты.
Правила игры — функции домена, которые проверяют команду и меняют
сущности. Прикладной слой вызывает только правила. Формулировка — в
[принципе 1](../architecture/zen/principles.md#1-правила--функции-домена).

**Последствия.** Правила живут в домене, а не в прикладном слое.
Прикладной слой не должен менять сущности напрямую — это стоит
закрепить автоматической проверкой импортов. Агрегат живёт в памяти по
ссылке, поэтому правило обязано сначала всё проверить и только потом
менять: иначе упавшее правило оставит агрегат полуизменённым.
