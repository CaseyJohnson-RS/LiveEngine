# 0004. Клиент строит картину мира сам

**Контекст.** Связь может рваться. Нужно было решить, как вернувшийся
клиент догоняет игру: номера событий, пересылка пропущенного,
подтверждения доставки — всё это заметно усложняло движок.

**Решение.** Клиент строит картину мира по приходящим сообщениям и в
любой момент может запросить снимок. Снимок — текущее состояние, а не
история. История событий — забота игрока; полная история доступна только
в логе в конце игры. Формулировка — в
[принципе 2](../architecture/zen/principles.md#2-клиент-воссоздаёт-картину-мира-сам)
и в [видимости](../rules/visibility.md).

**Последствия.** Не нужны номера событий и повторная пересылка:
переподключение — это запрос снимка. Домен обязан уметь отдать снимок для
конкретного игрока в любом состоянии. Пропущенные во время потери связи
события игрок не получит.
