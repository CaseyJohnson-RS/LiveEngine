# 0006. Изменяемые сущности, агрегат живёт в репозитории

**Контекст.** Документация утверждала, что доменный и прикладной слои не
хранят состояния, а код держал изменяемые сущности, живущие между
вызовами. Рассматривался и чисто функциональный домен: неизменяемые
снимки и функции «состояние → новое состояние».

**Решение.** Сущности изменяемые. Между вызовами агрегат живёт за
исходящим портом — в репозитории; адаптер репозитория держит его в
памяти. Прикладной слой не хранит состояния между вызовами. Формулировка —
в [гексагональной архитектуре](../architecture/zen/hexarch.md).

**Последствия.** Нужен порт репозитория и адаптер к нему. Меньше
переделок существующего кода. Преимущества функционального подхода
(бесплатная история, воспроизведение партии) отложены.
